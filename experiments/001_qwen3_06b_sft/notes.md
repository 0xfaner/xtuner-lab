## 实验 001：Qwen3-0.6B 真数据 SFT（E1）

- **目的 / 假设**：本地单卡（4080S）真模型 + 真数据基线；观察真实 loss 行为；用验证集对比"微调前 vs 微调后"，把过拟合判据落到真数据上。
- **实际命令**：`cmd.sh`（200 步）；自扩对照 `cmd_68.sh`（68 步 ≈ 1 遍数据）。模型配置 `config/e1_model_cfg.py`（两处修正：关 compile、关词嵌入共享）。
- **关键数字**：
  - 数据：alpaca GPT-4 中文 42,677 条 → 2000 train / 200 val（seed 42）；packing 后 1 遍 = 68 箱（4096 token/箱）。
  - 200 步训练：loss 2.21 → 0.52（末三步 0.48 / 0.32 / 0.52），126.66 s，max 12.38 GB / reserved 14.15 GB，末步 tgs ≈ 7.4k（exp_tgs 6.7k），全参 751.63 M；`hf-200` 已保存。
  - 68 步训练：loss 2.21 → 1.98，46.45 s；`hf-68` 已保存。
  - 验证集（200 条 held-out，assistant-only 的 token 平均交叉熵）：微调前 **2.19**；68 步（≈1 遍）后 **1.81**；200 步（≈3 遍）后 **2.33**——先降后升的迷你曲线，过拟合 + 早停证据链闭合。
  - 预测 vs 实际：起步 1.7 → 2.2；末步 0.8 → 0.5；显存 9.6 → 12.38；val 方向预测"降"（实际先降后升）。
- **踩坑与解决**：
  1. 流程：未完成模型/数据下载就执行后续步骤（已纠正）。
  2. **`RuntimeError: Unexpected keys in checkpoint: {'lm_head.weight'}`**——官方检查点带独立 `lm_head.weight`，而 config 写 `tie_word_embeddings=True`；从 config 推导会造"共享权重"模型（596.05 M），与检查点结构不符。修复：配置显式 `tie_word_embeddings=False`（与内置 `Qwen3Dense0P6BConfig` 一致）→ 参数量 596.05 M → 751.63 M。**官方文档的 `--load-from` 路径在 HEAD 6c06f96 + 官方 Qwen3-0.6B 上不能一把过。**
  3. `scripts/sample.py` 兼容：transformers 5.x `apply_chat_template(..., return_tensors="pt")` 返回 `BatchEncoding` 而非张量 → 取 `input_ids`。
  4. 无害警告备忘：flex_attention 回退（无 flash-attn）、bitsandbytes 无 GPU 二进制、`rope_parameters` 未识别键（XTuner 统一容器全量落盘所致）。
- **结论 / 未解问题**：
  - 小数据全参微调的过程验证：约 3 遍后训练 loss 崩塌（0.52 ≈ 强拟合），**验证 loss 不降反升（2.33，高于未训练的 2.19）**；对照 68 步（≈1 遍）val 降至 **1.81**——真数据版"过拟合 + 早停"证据链（2.19 → 1.81 → 2.33；E0 玩具实验的真模型版）。
  - 曲线最低点大概率在 1 遍附近（68 步上下）；更精确的"甜点位置"需补中间评估点。
  - 未解：val 的完整轨迹（本次只存终点，需中途 checkpoint + 多点评估）；数据量/步数的最优点（E2 更大规模上继续）。
